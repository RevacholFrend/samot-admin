📦 Игра

Игра распространяется через GitHub Releases: файлы игры или ПО прикреплены к релизу, а какие скачать решает манифест. Лаунчер скачает только изменённые файлы.

GitHub Releases
❓ Как выкатить новый релиз
  1. Соберите папку с готовой игрой (например, build/ после вашего сборщика).
  2. Запустите SAMOT Packager (кнопка скачивания чуть ниже в этом разделе): выберите папку игры, укажите версию и тег, нажмите «Собрать релиз». Появится папка game-dist/ с pack-*.zip, manifest.json и RELEASE-INSTRUCTIONS.txt.
  3. На GitHub → Releases → «Draft a new release» → задайте тег (например, v1.2.0) и описание.
  4. Залейте туда всё содержимое game-dist/ (manifest.json + все ассеты).
  5. Вернитесь сюда, введите этот же тег в поле «Тег релиза», нажмите «Проверить релиз на GitHub» — лаунчер увидит файлы.
  6. После успешной проверки нажмите «Сохранить». Кнопка «Скачать» в лаунчере будет качать игру по манифесту.

📎 Материалы для разработчиков

Всё, что нужно, чтобы подготовить игру к публикации: шаблоны изображений, скрипт сборки манифеста и короткая инструкция. Не видно игрокам.

Шаблоны изображений

Скачайте, впишите в рамки свой арт — и вставьте ссылку в настройках проекта. Мы не храним файлы картинок: заливайте куда угодно со стабильным URL (свой CDN, GitHub, свой сервер).

SAMOT Packager — сборка игры для релиза (.exe)

Отдельная программа для Windows: выбирает папку игры, пакует файлы в pack-*.zip, считает SHA-256 и формирует manifest.json + короткую инструкцию по публикации. Установка не требуется (portable), 72 МБ, подписана сертификатом SAMOT.

Запускается двойным кликом: папка игры → версия → «Собрать релиз» → готовая папка game-dist. Исходники и подробности — в репозитории samot-tools.

Как выпустить игру

  1. Соберите игру в отдельную папку (например, C:/Games/MyGame/build). Внутри должны лежать только финальные файлы.
  2. Запустите SAMOT Packager: папка игры → версия (1.0.0) и тег (v1.0.0) → «Собрать релиз». Рядом появится папка game-dist/ с manifest.json и pack-*.zip для релиза.
  3. Создайте релиз на GitHub в своём репозитории (например, owner/repo, тег v0.9.4) и загрузите в него содержимое game-dist/ как ассеты.
  4. В админке → «📦 Релиз и манифест» заполните: владелец репозитория, имя репозитория, тег релиза, версию игры, «Манифест» — вставьте JSON-файл целиком. Включите «Игра доступна для загрузки» и сохраните.
  5. Проверьте в лаунчере под тестовым аккаунтом: «Скачать игру» скачает только недостающие/сбитые файлы (проверка хэшей по манифесту).
  6. Обновление игры: та же сборка с новым тегом. Игроки получат только изменённые файлы.

Если игра ещё не готова — оставьте «Игра доступна для загрузки: Нет». Игроки увидят карточку, но кнопка скачивания будет скрыта.

📚 Вики разработчика

Краткая справка для всех разработчиков, у которых есть доступ к этой админке. Игра здесь не требуется — всё описано на уровне поиска и не дублирует код.

Кто вы в этой системе

Вы — разработчик. В обычной роли (editor) вы можете:

  • менять новости, настройки, скриншоты своего проекта;
  • загружать и обновлять файлы игры или ПО через GitHub Releases;
  • видеть статистику по своему проекту;
  • связываться с командой и просить разбан;
  • видеть предупреждения своего проекта (если вы владелец (owner)).

Что вы не можете в обычной роли (для этого нужен владелец проекта или супер-администратор SAMOT):

  • видеть и менять чужие проекты;
  • создавать новый проект (обратитесь к супер-админу);
  • выдавать доступ к админке другим людям;
  • удалять чужие проекты;
  • банить игроков (только супер-администратор);
  • отправлять предупреждения игрокам (только владелец и супер-администратор);
  • определять публичную главную карусель лаунчера и «Последние новости» на Главной.
Разделы админки, кратко

📰 Новости проекта — публикации для игроков: заголовок, тег, картинка, текст. Флаг «Показывать в «Последних новостях» на Главной» — только для супер-администратора. «📺 В карусель» тоже только для super-админа.

⚙️ Настройки проекта — название, версия, заметки к обновлению, переключатели видимости кнопки скачивания, ссылка на установщик, медиа-поля (баннер, обложка, скриншоты, описание). Сохраняет всё разом.

📦 Релиз и манифест — связь с GitHub Releases и манифестом SHA-256 для дельта-обновления. Гайд ниже в «Релизах».

👥 Команда проекта — кто входит в команду. Вы (owner) можете приглашать участников по email — роль editor/owner.

⛔ Баны и разбаны — баны с причиной и сроком, только супер-администратор. ⚠️ Предупреждения — мягкая ступень до бана: выдавать и отзывать могут владелец проекта и супер-администратор.

🐞 Баг-репорты — сообщения игроков и разработчиков. Если собрали баг — выгрузите, чтобы знать, что чинить.

📎 Разработчику — шаблоны изображений, скрипт сборки манифеста, пошаговая инструкция выпуска релиза.

📊 Аналитика — сводка по запускам и активности игроков (только супер-администратор).

🗞️ Новости SAMOT — новости от лица бренда и события (фестивали/акции), только супер-администратор.

Как залить новую игру (первый раз)
  1. Соберите игру в папку (например, C:/Games/MyGame/build).
  2. Запустите SAMOT Packager — получите game-dist/ с manifest.json и pack-*.zip для релиза.
  3. Создайте релиз на GitHub в своём репозитории (тег v0.9.4) и загрузите файлы из game-dist/ как ассеты.
  4. В этой админке → «📦 Релиз и манифест» заполните: владелец, репозиторий, тег, версию, вставьте manifest.json целиком.
  5. Сохраните. Включите «Игра доступна для загрузки».
  6. Проверьте в лаунчере под тестовым аккаунтом: кнопка «Скачать» будет качать только отсутствующие/сбитые файлы.

Если игра в разработке: оставьте «Игра доступна для загрузки» в положении «Нет». Игроки увидят карточку, но скачивать ничего не будут.

Как выпустить обновление
  1. Соберите новую версию игры тем же SAMOT Packager: укажите версию 0.9.5, тег v0.9.5.
  2. Создайте новый тег релиза на GitHub (например, v0.9.5) и загрузите в него ассеты.
  3. В этой админке → «📦 Релиз и манифест» поменяйте: тег релиза → v0.9.5, версию игры → 0.9.5, вставьте свежий manifest.json.
  4. Кнопка «Сохранить все настройки».

Игроки при следующем запуске увидят, что доступно обновление, и получат только изменённые файлы.

Важные правила
  • Пароли не пересылайте даже коллегам. Ваша сессия — ваш ключ. Распространение пароля — мгновенная блокировка.
  • Картинки — только по ссылкам. Мы не храним файлы обложек и скриншотов. Заливайте куда угодно (свой CDN, облако, GitHub raw) — ставьте URL в настройках проекта.
  • Не удаляйте проект без согласования. Удаление каскадно сносит всё (новости, настройки, участники).
  • Бан — это крайняя мера. Сначала предупреждение в чате/сообщении, затем временный бан, затем бессрочный. Всегда указывайте причину и срок.
  • Безопасность важнее скорости. Если заметили уязвимость — сообщите супер-админу через «Баг-репорты» до того, как этим кто-то успел воспользоваться.
  • ПД персональных данных. То, что игрок сам сообщает в баг-репорту — личное. Не передаём, не пересылаем, не публикуем. Доступ — только коллегам по проекту.
Полезные ресурсы (по опыту разработки под SAMOT)

Картинки в проекте — только по ссылкам, и хостинг должен отдавать файл быстро и долго. Ниже — сервисы, которые мы рекомендуем. Порядок: от «бесплатно и навсегда хватает» к «когда растёте».

Хостинг картинок и ассетов (баннеры, обложки, скриншоты, миниатюры)

  • GitHub raw — файлы из вашего репозитория раздаются напрямую: raw.githubusercontent.com/…. Бесплатно, без регистрации, ссылка стабильна годами. Кладёшь файл в репозиторий — копируешь ссылку из адресной строки.
  • Release assets — тот же репозиторий, файлы прикрепляются к релизу (/releases/download/…). Так живут манифесты игры; годится и для картинок, которые должны быть привязаны к версии релиза.
  • Cloudinary (бесплатный тариф) — настоящий CDN: авто-подгон размеров и форматов (webp для Photoshop-веба, webp/avif), быстрый отклик, прямые ссылки. Подходит, когда картинок много или нужен именно CDN.
  • Supabase Storage — если хотите держать файлы в том же Supabase, где хранятся данные проекта (bucket news/assets). Удобно, но помните: в бесплатном тарифе лимит 1 ГБ.
  • i.ibb.co — простейший бесплатный хостинг без регистрации. Только для тестов и временных нужд: ссылки могут протухать без предупреждения.

Хостинг самой игры / билда

  • GitHub Releases — основной способ. Публичные артефакты, теги версий, до 2 ГБ на файл. Именно так устроена загрузка через SAMOT Packager (pack-*.zip + manifest.json).
  • Cloudflare R2 — если GitHub станет узким местом (много игроков, частые обновления): бесплатно первый ГБ хранения и исходящего трафика, дальше копейки.

Инструменты для картинок

  • ShareX (Windows) — скриншоты, захват области, аннотация и загрузка в один клик сразу на ваш хостинг.
  • Squoosh — сжатие изображений в браузере без заметной потери качества.
  • TinyPNG — быстрое сжатие PNG/WebP (онлайн).

Справочники

  • GitHub Docs (docs.github.com) — releases, permissions, raw-ссылки, лимиты.
  • MDN Web Docs — если делаете лендинг или страницу-заглушку (HTML/CSS/JS).
  • Stack Overflow — задавайте вопрос с минимумом кода и ошибкой в кавычках; 90% задач уже решены до вас.

Дисклеймер: сторонние сервисы могут менять условия в любой момент; ссылки приведены для удобства и не являются рекламой. Пруфите SHA-256 любых загрузок через встроенный certutil -hashfile <file> SHA256.

Кому писать при вопросах

Быстрые вопросы — повторите, что в «📎 Разработчику» (гайд и шаблоны).

Не получилось — «🐞 Баг-репорты» → «Отправить сейчас». Ответ придёт асинхронно, почта у нас скрыта — просто пишите, о чём вопрос.

Срочно нужно добавить команду / создать проект / выдать доступ — пишете супер-администратору вашего проекта, он решает.
